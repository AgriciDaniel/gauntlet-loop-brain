# AI Marketing Hub Integration

Integrate the Gauntlet Loop as an opt-in quality lane behind the existing task
router. It should receive a routed job and return evidence plus an outcome. It
must not reroute the task, mutate governed catalog truth, publish, deploy, spend,
or inherit external authority.

## Shared core

The shared Gauntlet adapter owns:

- fit assessment;
- the frozen job contract;
- reference and rubric metadata;
- coupling-aware decomposition;
- builder and critic separation;
- iteration and budget state;
- protected evaluator routing;
- integration and regression checks;
- stop reason and final outcome vocabulary.

## Domain adapters

Each domain owns its real acceptance criteria.

- Ads: product truth, brand, policy, message, and creative quality. No launch or
  performance prediction without campaign evidence.
- Blog: source support, structure, originality, voice, usefulness, and declared
  search constraints.
- SEO: technical validity, search intent, source quality, and current official
  platform guidance. No ranking guarantees.
- Landing pages and UI: rendered states, accessibility, interaction, responsive
  behavior, performance, brand direction, and distinctiveness.
- Research: source quality, claim coverage, contradiction handling, and
  reproducibility. Eloquence is not evidence.
- Product pages: visible product facts, review integrity, schema parity,
  accessibility, jurisdiction-specific checks, and conversion craft.

## Pilot gate

Start with one opt-in skill whose output is fully inspectable and already has
deterministic gates. Compare it against the current simpler workflow at an equal
budget. Measure accepted-result quality, regressions, elapsed time, tokens, and
human review effort. Do not generalize from one successful demo.

Promote the shared adapter only after the pilot shows a decision-relevant gain
without weakening protected gates or authority boundaries.
